# Pattern Detector

## Purpose
Aggregate incidents by type, actor, time, and place to calibrate isolated versus systematic language.

## When To Use
Use when the active situation needs Pattern language is a legal and evidentiary threshold, not a stylistic flourish. and the user wants a structured, reviewable marketplace run.

## When Not To Use
Do not use when the case lacks any relevant actors, claims, events, or source receipts. Run context preparation or ingestion first when the user needs grounded assertions.

## Inputs
Analyst prompt, active case context, ontology requirements (human-rights), source receipts, graph snippets, and optional focused node or prior tool output.

## Outputs
Structured summary, evidence-grounded findings, synthesized options where appropriate, confidence and gap notes, next actions, and a preserved context dump.

## Context Requirements
Requires user role/preferences, workspace methodology when available, active case graph context, conversation focus, and graceful handling for weak context. Minimum context health target: 45%.

## Composition
Can follow human-rights.violation-tracker. Can chain into: cross.brief-exporter

## Examples
Run Pattern Detector against the active case and export accepted findings to the workbench evidence drawer or Memo Studio.

## Pitfalls
Do not turn synthesized output into durable graph assertions without review. Keep missing receipts, ontology mismatch, and low confidence visible as advisories.
