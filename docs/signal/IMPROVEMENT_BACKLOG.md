## Geographic coverage contract

An optional `coverageCountry` is an explicit analyst mapping of a captured source revision. It does not establish publication origin, a publisher's headquarters, language-derived geography or an independently verified event location. Do not infer it from language, URL suffix, outlet name or the selected desk scope. Unmapped sources remain visible as unmapped; assigning a desk country must not invent captured coverage.

Selected countries describe the analyst's desk scope and receive a distinct outline. Actual coverage counts require current captured source heads with an explicit mapping; superseded revisions and withdrawn heads must not silently inflate those counts. Provide the mapped and unmapped denominator alongside the geographic view and a list fallback. A selected country with no captured evidence has zero captured coverage even when its outline is prominent. Map counts are bounded source-panel observations, not complete national media coverage or population belief.

Use local Natural Earth public-domain boundaries with a retained provenance/version notice. If a country lacks a usable boundary or geographic reference anchor in the selected asset, disclose the missing geometry, keep the source/count in the accessible list, and avoid fabricating a location. Verify multi-part geometries, antimeridian behavior, projection orientation and source-marker country alignment in the actual browser. Synthetic QA examples must be labelled and cleaned up; they cannot stand in for real customer geography or human evaluation.

The optional mapping belongs inside the existing source payload, which already has indexing disabled. No new infrastructure or additional indexes are required for that optional nested field. The evidence network remains available as an additional relationship/review view rather than replacing the geographic coverage task.

## Further geographic improvements

- Extend locally licensed reference anchors for registry territories absent from the 110m dataset. Accept only documented coordinates with clear provenance; retain the explicit not-plotted state until those coordinates are verified.
- Evaluate explicit multi-country source annotation for cross-border evidence. Preserve immutable metadata revisions and avoid multiplying source-family totals when a single source covers several countries.
- Test country search and a center-selected-country control with real reviewers, especially for countries on the far side of the globe. Keep keyboard and list inspection equivalent to pointer navigation.

## Private feedback workflow

The candidate accepts append-only feedback inside the owned desk through the same authenticated, optimistic-version mutation path as other desk actions. It records the actor, timestamp and desk revision. Areas are Overview, Coverage, Narratives, Evidence, Context and Briefs; categories are usability, visualization, source coverage, evidence review, brief export and other. Ratings are integers from 1 to 5 and notes contain 5–1,500 characters. A desk retains at most 30 notes. Test submissions must set the synthetic flag.

Feedback is a product note, not a source-reading acceptance, a capsule promotion or an approved brief change. It remains private in the desk; the owner can export private feedback JSON and choose whether to share it. There is no automatic external message or feedback transmission. Desk deletion removes its notes with the rest of the owned desk. Exports must be treated as private material; do not commit real analyst notes, personal identifiers or credentials into fixtures or this repository.

The new `signalDesks.feedback` field has an explicit empty Firestore index configuration, matching other large desk payloads. Publication is additive and must retain all previous SIGNAL indexes and suppressions. Record readback separately from application release readiness: adding an index exemption does not deploy the feedback UI or prove its authenticated workflow.
