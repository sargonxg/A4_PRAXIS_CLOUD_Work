## Strategic stance: open-source data only

PRAXIS now ships exclusively on:

- **Open-license data feeds** — GDELT (BigQuery public dataset), UCDP
  GED (CC-BY 4.0), ReliefWeb, HDX HAPI, UNHCR, World Bank, UN News,
  Wikipedia, plus the BigQuery Marketplace open datasets (GHCN, NOAA,
  WHO, Census, IMF).
- **Google services we already pay for through GCP** — Gemini 3 Flash
  + 3.1 Pro, Vertex AI Deep Research (Reasoning Engine), Google Search
  Grounding.
- **No third-party paid data licenses, no third-party scrapers.**
  ACLED Corporate License, Firecrawl, Anthropic Claude, Tavily,
  Parallel.ai are all out — we don't sell our customers data we
  haven't licensed openly.

Everything below reflects that posture.

## 1. Vertex AI Agent Engine — full deploy walk-through

**Why:** The Deep Research Agent today silently falls back to plain
Gemini grounded search because `VERTEX_AGENT_ENGINE_ID` is unset.
Deploying the engine unlocks the planner → researcher → synthesizer
3-phase agentic flow, which is now the flagship differentiator (since
we removed ACLED, our intelligence story is "Vertex AI multi-agent
research grounded in open data").

**Expected outcome:** `/api/health` reports `vertex_adk: 'ok'`.
Visiting `/app/deep-search-agent` and asking a question returns
streaming structured Markdown with citations, generated by the
multi-agent pipeline rather than the fallback.

This walk-through is grounded in compass research §R1 (verified
2026-04-25). Pin the exact versions below — Agent Engine moved fast in
late 2025 / early 2026 and older recipes are broken.

### 1.1 Pre-flight (one-time)

```bash
# Set project and region
gcloud config set project praxisbytacitus
gcloud config set run/region us-central1

# Enable APIs
gcloud services enable aiplatform.googleapis.com storage.googleapis.com --project=praxisbytacitus

# Create the staging bucket the ADK uploads code to
gsutil mb -p praxisbytacitus -l us-central1 gs://praxisbytacitus-agent-staging
```

### 1.2 Backend scaffolding (already in repo)

Engineering already created `backend/agents/` with the deploy script.
You only need Python locally:

```bash
cd backend/agents
python3 -m venv .venv
source .venv/bin/activate    # Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

That installs:

```
google-cloud-aiplatform[adk,agent_engines]>=1.148.1
google-adk==1.31.1
google-genai>=1.0.0
```

(Python 3.10–3.12 — Agent Engine doesn't yet support 3.13+.)

### 1.3 Authenticate to GCP

```bash
gcloud auth application-default login
```

### 1.4 Deploy

```bash
python deploy.py
```

The script registers a 3-phase Reasoning Engine (planner /
researcher / synthesizer) and prints the resource path:

```
projects/852128226674/locations/us-central1/reasoningEngines/<NUMERIC_ID>
```

Save the `<NUMERIC_ID>`.

### 1.5 IAM

```bash
gcloud projects add-iam-policy-binding praxisbytacitus \
  --member="serviceAccount:852128226674-compute@developer.gserviceaccount.com" \
  --role="roles/aiplatform.user"
```

(There is **no** `roles/aiplatform.reasoningEngineUser` role as of
April 2026 — `roles/aiplatform.user` is the canonical invoker role.)

### 1.6 Store the engine ID and wire to Cloud Run

```bash
echo -n "<NUMERIC_ID>" | gcloud secrets create praxis-vertex-adk-engine-id \
  --data-file=- --project=praxisbytacitus
gcloud secrets add-iam-policy-binding praxis-vertex-adk-engine-id \
  --member="serviceAccount:852128226674-compute@developer.gserviceaccount.com" \
  --role="roles/secretmanager.secretAccessor" \
  --project=praxisbytacitus
```

Edit `cloudbuild.yaml` — find the frontend deploy step and append
`,VERTEX_AGENT_ENGINE_ID=praxis-vertex-adk-engine-id:latest` to the
existing `--update-secrets` flag.

### 1.7 Redeploy and verify

```bash
gcloud builds submit --config=cloudbuild.yaml --project=praxisbytacitus
curl -s https://praxis.tacitus.me/api/health | jq '.checks.vertex_adk'   # expect "ok"
```

### 1.8 Costs

vCPU $0.0864/hr + RAM $0.0090/GB-hr + Gemini token cost per phase. A
typical 3-phase research run is a few cents. Daily spend at 50
researches is ~$5–8. Billed inside the praxisbytacitus GCP project —
no third-party vendor.

## 2. Switch Cloud Run to the Vertex AI provider

**Why:** Compass §R8 — same per-token price as AI Studio, but adds
IAM, data residency, SLA, and VPC-SC, all required by UN/EU buyers.

**Step-by-step:**

1. Edit `cloudbuild.yaml`, frontend deploy step. Find the
   `--set-env-vars` line. Add `AI_PROVIDER=vertex` if not present, or
   change `AI_PROVIDER=googleai` to `AI_PROVIDER=vertex`.
2. The Cloud Run service account already has `roles/aiplatform.user`
   (we set it during the Vertex ADK step in §1).
3. `gcloud builds submit --config=cloudbuild.yaml --project=praxisbytacitus`.
4. Verify: `curl -s https://praxis.tacitus.me/api/health/provider | jq` —
   should report `vertex: true`.

**Why this matters strategically:** Once UN procurement conversations
start, the buyer will ask "where is our data processed?". With Vertex
AI you can answer "any GCP region you choose, including
`europe-west1` (Belgium) or `europe-west4` (Netherlands)".

## 3. GDELT BigQuery hot slice (open-data backbone)

**Why:** GDELT GKG (Global Knowledge Graph) publishes a new file every
15 minutes. Google maintains a free BigQuery mirror at
`gdelt-bq.gdeltv2.gkg_partitioned`. Rather than re-poll raw CSV files,
materialise a hot 7-day slice into our own `praxis_analytics` dataset,
partitioned by date and clustered by `(situation_id, country_code)`.
Sub-200ms per-situation reads, free under 1 TB/month.

**Authoritative playbook:** `docs/implementation/gdelt-ingestion-2026-04-25.md`
(1,036 lines, step-by-step). Cap notes here:

1. Run the bq query from playbook §1 to verify your ADC creds reach
   the public dataset.
2. Create two service accounts per playbook §2:
   - `praxis-gdelt-poller` (Cloud Run Job that materialises the slice)
   - `praxis-gdelt-reader` (backend reader)
3. Apply the table DDL from playbook §3 (`praxis_analytics.gdelt_situation_events`,
   partitioned by `DATE(event_ts)`, clustered by
   `(situation_id, country_code)`).
4. Build the Cloud Run Job from playbook §4 — this is delegable to
   Codex / Claude Code; you only authorise the deploy.
5. Schedule via Cloud Scheduler every 15 min per playbook §5.

**Cost ceiling:** $2–5/month at MVP scale, cap-tested by the playbook.
**Hard expectation:** sub-200ms cached reads, sub-4s cold.

## 4. Stripe billing — products, prices, webhook

**Why:** Until configured, `/api/stripe/checkout` returns 503 and
nobody can pay you. Compass §R6 chose Stripe Billing + hosted Pricing
Tables + Entitlements API + the Invertase `firestore-stripe-payments`
extension + v2 Meters API for overages.

**Step-by-step:**

1. Visit https://dashboard.stripe.com/, finish account setup.
2. Products → create:
   - **PRAXIS Analyst** — recurring monthly $49.00
   - **PRAXIS Team** — recurring monthly $199.00
   - (Enterprise: do not create a fixed price; sales-led only.)
3. Copy the price IDs (start `price_…`) for each.
4. Set up the webhook:
   - Endpoint URL: `https://praxis.tacitus.me/api/stripe/webhook`
   - Events: `customer.subscription.*`, `invoice.paid`,
     `invoice.payment_failed`,
     `entitlements.active_entitlement_summary.updated`
   - Copy the webhook signing secret (`whsec_…`).
5. Install the Invertase extension in Firebase:
   - Firebase Console → Extensions → "Run Payments with Stripe"
   - Connect to project `praxisbytacitus`.
6. Store secrets:
   ```bash
   echo -n "sk_live_..." | gcloud secrets create praxis-stripe-secret \
     --data-file=- --project=praxisbytacitus
   echo -n "whsec_..." | gcloud secrets create praxis-stripe-webhook-secret \
     --data-file=- --project=praxisbytacitus

   for s in praxis-stripe-secret praxis-stripe-webhook-secret; do
     gcloud secrets add-iam-policy-binding $s \
       --member="serviceAccount:852128226674-compute@developer.gserviceaccount.com" \
       --role="roles/secretmanager.secretAccessor" \
       --project=praxisbytacitus
   done
   ```
7. Edit `cloudbuild.yaml`:
   - `--update-secrets`: `STRIPE_SECRET_KEY=praxis-stripe-secret:latest,STRIPE_WEBHOOK_SECRET=praxis-stripe-webhook-secret:latest`
   - `--set-env-vars`: `STRIPE_PRICE_ANALYST=price_xxx,STRIPE_PRICE_TEAM=price_yyy`
8. Redeploy.
9. Test with `4242 4242 4242 4242`.

## 5. SOC 2 Type II — engage an auditor

**Why:** Compass §R10 — required by UN agencies, EU missions, large
NGOs. 4–9 month timeline, $25–50k all-in.

**Step-by-step:**

1. Get quotes from three: Drata, Vanta, Secureframe.
2. Pick one (Drata is most common for GCP-first startups).
3. Set scope: minimum **Security + Availability + Confidentiality**.
   Add Privacy if selling to EU residents (you do).
4. They'll deploy automated evidence collection agents.
5. Type I: 90 days. Type II observation window: +6 months.
6. Realistic Type I sign-off in Q4 2026 if started this sprint.

**Where to paste results:** `docs/legal/soc2-engagement-YYYY-MM-DD.pdf`
for the SOW. Update `docs/COMPLIANCE.md` §2.1 quarterly.

## 6. UNGM — register at Level 2

**Why:** Required to bid on UN agency contracts >$500k.

**Step-by-step:**

1. https://www.ungm.org/Vendor/Registration → start a new vendor
   registration.
2. Have ready: company registration certificate, VAT/EIN, 2 banking
   references, 2 client references (academic OK at Level 2),
   audited financials (or letter of explanation if pre-revenue),
   product/service description matching UNSPSC codes (PRAXIS maps to
   `81141500 Risk management consulting services` and
   `83121701 Information research services`).
3. Submit. Approval typically 4–8 weeks.

**Where to paste results:** Update `docs/COMPLIANCE.md` §2.4.

## 7. DPA + sub-processor list publication

**Why:** Required by every enterprise prospect.

**Step-by-step:**

1. Use a template DPA (Iubenda generator or lawyer draft) covering
   GDPR Art. 28 + ISO 27018 cloud-PII clauses.
2. Inventory sub-processors (already drafted in `docs/COMPLIANCE.md`
   §3): **Google Cloud only** is now the operational data path —
   Stripe joins when monetising, that's it. No ACLED, no Firecrawl,
   no Anthropic, no third-party scrapers.
3. Publish at:
   - `/legal/dpa.pdf` — the DPA template
   - `/legal/sub-processors` — table with vendor + purpose + region
4. Add footer link: "Compliance → /legal".
5. Lawyer review before publishing — €1–3k for a templated DPA.

## 8. Activate audience-tuning in production

**Why:** Engineering shipped audience-tuned briefing presets behind
`PRAXIS_AUDIENCE_TUNED_BRIEFING=1`. Activate when you want
`auto-briefing`, `dashboard-summary`, and `briefing-generate` to
explicitly enforce the AnalystProfile audience tone.

**Step-by-step (5 min):**

1. Edit `cloudbuild.yaml`, frontend deploy step, `--set-env-vars`.
2. Append `,PRAXIS_AUDIENCE_TUNED_BRIEFING=1`.
3. `git commit -am "ops: turn on audience-tuned briefings in prod"`.
4. `gcloud builds submit --config=cloudbuild.yaml --project=praxisbytacitus`.
