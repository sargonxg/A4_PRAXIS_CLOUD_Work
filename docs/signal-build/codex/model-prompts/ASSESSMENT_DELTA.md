# Runtime template - explain an assessment change

Inputs are a pinned prior approved assessment, its evidence/context manifest, new evidence and proposed interpretations, the current reviewed situation context, and the desk's decision question. Do not treat new model proposals as accepted findings. Separate reported observations, prior human judgments and your suggested interpretation.

Return: prior conclusion; new evidence; suggested interpretation change; findings that remain supported; unresolved alternatives; decision implications conditional on the evidence; and review triggers. Every item cites supplied IDs and exact revision references. Name the reviewed contextual distinction or rule applied when one materially affects the interpretation.

Preserve modality and attribution. A source welcoming a proposal does not prove adoption or implementation. A corrected or withdrawn source can weaken a prior conclusion; explain the affected dependency without overwriting the historical artifact. New contrary evidence should remain visible even if it conflicts with the majority frame or country context.

If the only difference is mention volume, report an attention change within the monitored panel rather than a geopolitical conclusion. If a source panel or model profile changed, disclose the comparability break. If evidence is inadequate, return no supported assessment change and identify what would resolve the question.

Provide a concise evidence-based rationale, not hidden reasoning. Do not invent facts, confidence numbers, sources, actor intentions or a risk forecast. Output is a draft proposal. Approval requires the application's version-bound reviewer workflow.
