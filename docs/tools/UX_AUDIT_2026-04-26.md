# PRAXIS Tool-by-Tool UX Audit — 2026-04-26

Read-only audit. 13 priority tools. Source files: `src/lib/constants/tool-registry.ts`, each tool's `page.tsx`, each `/api/ai/<tool>/route.ts`, `src/lib/api/save-tool-output.ts`, `src/hooks/useToolData.ts`, `src/hooks/use-persisted-tool-data.ts`, `src/lib/services/tool-data-service.ts`.

Persistence layers in play (collection: `users/{uid}/situations/{sitId}/tools/{toolId}`):
- `useToolData(name)` — client onSnapshot using a `ToolName` union (mostly underscores).
- `usePersistedToolData(id, sitId)` — `/api/tool-data` fetch keyed by registry id (mostly hyphens).
- `saveToolOutput({ toolId })` — server admin write inside calibrated routes.
- `withCalibration(toolId, op)` — auth + credit + analyst-profile gate; injects `<analyst-profile>` + `<situation-frame>` + `<output-constraints>` block.

### Tool: PRAXIS Assistant (Ask PRAXIS)

- Tool registry id: `assistant`
- Page file: `src/app/app/assistant/page.tsx` (delegates to `src/components/assistant/chat-interface.tsx`)
- API route file: `src/app/api/ai/chat/route.ts`
- Question this tool answers: anything PRAXIS — research, drafting, terminology, situation Q&A.
- Required situation context: none mandated; assistant works without a situation.
- Trusted sources / feeds expected: ACLED, GDELT, Firecrawl, document RAG via `retrieveRelevantChunks`.
- Output schema: streaming text + AI SDK 6 tool-call invocations (21 specialist tools).
- What it writes back: `saveToolOutput({ toolId: 'chat' })` on assistant turns when a `situationId` is present.
- useSituationGuard: yes (also `needsOnboarding`)
- withCalibration: yes — `withCalibration('chat', 'ai_chat', ...)`
- usePersistedToolData: no — chat history lives in `useChat` React state only.
- Citations / confidence: partial — system prompt enforces `[ACLED]/[GDELT]/[Web]` source badges and HIGH/MEDIUM/LOW labels, but no UI affordance for inspecting them.
- Empty / loading / error states: good empty (phase-aware suggested prompts), `Loader2` while streaming, no dedicated error view.
- Export / share path: no — `Download` icon imported but no transcript export wired.
- Visible bugs or disconnected UX:
  - Chat history not persisted across navigation; switching tabs loses the conversation.
  - `DEMO_CONFLICT_CONTEXTS` array still hard-codes the selected situation/DRC/etc. instead of deriving from active situation.
  - System prompt claims "30+ tools"; registry has 46.
- Recommended low-risk fix: persist last N turns under `tools/chat` via `saveToolOutput` and reload on mount.
- Recommended next major brick: rebuild the assistant as a project-aware notebook — every turn gets a turn id, a citation panel that surfaces the streamed `ToolInvocation` calls, and a "Promote to report section" action that pipes a turn into Report Studio. This is the wedge that converts chat into structured deliverables.

## Cross-tool findings

### Persistence inconsistencies (tool-data vs tools paths, hyphen vs underscore IDs)

Single canonical Firestore collection: `users/{uid}/situations/{sitId}/tools/{toolId}`. Three diverging vocabularies for `toolId`:

1. **Registry id** (mostly hyphen): `conflict-graph`, `early-warning`, `media-roundup`, `auto-briefings`, `legal-tracker`, ...
2. **`ToolName` union** consumed by `useToolData` / client `tool-data-service.ts` (mostly underscore): `risk_assessment`, `media_analysis`, `conflict_graph`, plus the Group-8 hyphenated exceptions (`legal-tracker`, `human-rights`, `external-actors`, `electoral-risk`, `economic-impact`, `peacebuilding-index`).
3. **Server `withCalibration` toolId** at write time (mostly underscore): `risk_assessment`, `briefing_room`, `daily_brief`, `policy_memo`, `escalation_scan`, `conflict_graph`, ...

Concrete drift cases observed:

| Tool | Registry id | Server write id | Client read hook id |
|---|---|---|---|
| Conflict Graph | `conflict-graph` | `conflict_graph` | `conflict-graph` (persisted) |
| Briefing Room | `briefing` | `briefing_room` | `briefing` |
| Daily Brief | `auto-briefings` | `daily_brief` | `auto-briefing` (persisted) |
| Early Warning | `early-warning` | `escalation_scan` | `early_warning` (shell) |
| Legal Tracker | `legal-tracker` | `commitments` (BUG) | `legal-tracker` |
| Media Compass | `media-compass` | `media_compass` | `media-compass` and `media_analysis` |
| Media Roundup | `media-roundup` | `media_roundup` | `media-roundup` and `media_roundup` |

Each row above is a place where an analyst can hit "Regenerate", see a fresh result on screen, navigate away, come back, and find the page empty.

Fix shape: a single `TOOL_PERSISTENCE_KEY` constant per tool used by every layer (route, hook, registry). Registry id should win.

### Calibration coverage gaps

- `legal-tracker` route calibrates as `commitments` — unintentional; Legal Tracker shares the Commitment Tracker calibration slot. This is a one-line fix.
- `humanitarian` has no dedicated AI route — the registry advertises `/api/ai/chat`. The humanitarian page does not benefit from `withCalibration('humanitarian', ...)`. Output language, red-line clauses, and audience tone are not applied to humanitarian briefs.
- Several routes share a calibration slot intentionally (`un-toolkit`, `terminology`, `resolution` all → `un_toolkit`; `advisor-chat`, `advisory`, `claude-analyze`, `sat` all → `advisory`). These are fine but should be documented.

### Citation / confidence gaps

Most schemas carry `confidence` or `intelligenceGaps` but the rendered UI rarely surfaces them:

- Assistant: badges enforced in the system prompt, not in render.
- Conflict Graph: per-entity confidence not displayed.
- Briefing Room: per-slide `sources[]` shown, no per-claim provenance.
- Risk Monitor: composite shown without confidence band.
- Policy Memo: no confidence field in schema at all.
- Legal Tracker: no per-resolution source link.
- Humanitarian: no per-figure attribution.

Tools that get this right today: ARGUS (`ConfidenceBadge`), Dossier (top-level `confidence` + `intelligenceGaps`), Deep Research Agent (phase-by-phase author tagging).

### Empty / error state gaps

Most pages have decent empty states (`AiPopulate` and `ToolPageShell` patterns are solid). Recurring weakness is **error handling** — a 500 typically yields a `console.warn` and an unchanged UI. Adopt a `Toast` from shadcn/ui or a banner component as a platform standard.

Demo / live confusion is the second pattern: at least four pages (Risk Monitor, Negotiation Prep, ARGUS, Humanitarian — also Conflict Graph in part) render demo-only data structures even in `!isDemo`.

### Top 5 highest-impact tool fixes ranked

1. **Fix Legal Tracker calibration** — change `withCalibration('commitments', ...)` to `withCalibration('legal_tracker', ...)` in `src/app/api/ai/legal-tracker/route.ts`. One-line fix; restores tool-correct prompt context, credit metering, and provenance.
2. **Unify the persistence vocabulary** — pick the registry id (hyphen) as canonical, add it to the `ToolName` union, migrate writes for `briefing_room → briefing`, `daily_brief → daily-brief`, `escalation_scan → early-warning`, `conflict_graph → conflict-graph`, `policy_memo → policy-memo`. After this, hook reads stop being a guessing game.
3. **Build `/api/ai/humanitarian`** with a `HumanitarianSnapshotSchema`, persistence, and calibration. The current page is the lowest-quality surface in PRAXIS relative to how much registry copy promises.
4. **Negotiation Prep: drive parties from the live situation** — render `situation.actors` instead of `NORDALIA_PARTIES` in `!isDemo`, and consume `actor_profiles` output for interests / leverage / red lines.
5. **Documents: add document → entity → graph cross-links** — a single `?docId=` deep-link on Conflict Graph and a "view originating paragraph" hover on every graph node. This converts Documents from a file cabinet into the explainability spine.

### Cross-tool patterns worth flagging in CHANGELOG / CONTINUATION

- Three id vocabularies for the same Firestore collection — needs a single canonical key per tool.
- One unintentional calibration mis-assignment (`legal-tracker → commitments`); document the intentional shared slots (`un_toolkit`, `advisory`).
- Demo data leaks into live mode on Risk Monitor, Negotiation Prep, ARGUS, Humanitarian, Conflict Graph; needs a platform-level demo-fallback badge rule.
- Page sizes >1,500 lines (Conflict Graph, Documents, Negotiation Prep) are now the norm; future work should split per surface (graph / list / detail) before adding features.
- Citation / confidence rendering is inconsistent; extract a shared `<Citation>` and `<ConfidenceBadge>` so every tool surfaces these the same way.
