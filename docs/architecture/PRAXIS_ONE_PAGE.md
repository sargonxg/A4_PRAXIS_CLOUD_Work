# PRAXIS in One Page

Last updated: 2026-05-07

PRAXIS is a workbench for policy, conflict, mediation, diplomacy, and analytic teams. It turns messy situation material - user preferences, case notes, uploaded sources, research threads, graph candidates, structured analytic techniques, tools, memos, and briefings - into reviewable, cited work products. the selected situation is one demo case; the product is the reusable operating room for any policy/conflict situation.

## What Users Can Do

- Create or open a situation, then work in one mounted workbench instead of jumping between many disconnected tools.
- Use four substrate tabs: **Context**, **Library**, **Ontology**, and **Graph**.
- Use seven work chapters: **Desk**, **Research**, **Memos**, **Draft**, **ACH**, **Tools**, and **Boardroom**.
- Upload sources, save a four-field situation frame, open research threads, run graph-grounded recipes, draft memos and briefings, inspect graph structure, read the case through map/timeline/stakeholder/anatomy views, and keep generated work advisory until a user reviews it.
- Export Markdown/DOCX/PDF-style work products while retaining provenance, audit notes, and context snapshots.

## Architecture Shape

The Next.js app renders the landing page, authenticated app surfaces, settings, admin, and API proxy routes. The Python backend owns workspace tab/chapter contracts under `backend/routers/tabs.py`, `backend/routers/chapters.py`, and `backend/routers/workspace.py`. Postgres stores durable workspace objects such as situation frames, source receipts, research threads, memos, drafts, recipe runs, suggestions, and pending Cognee writes. Firebase/Auth gates user identity and app access. Cognee is the intended knowledge-graph and memory substrate behind `backend/services/cognee_memory.py`; today the routes are deliberately disabled-safe and queue work if the isolated live Cognee service is unavailable.

The rule is simple: **tabs build and inspect the substrate; chapters create work products from it.** Tabs may write substrate tables such as frames and source receipts. Chapters write chapter products such as memos, drafts, research threads, ACH helpers, recipe runs, and briefings. Graph promotion and canonical fact changes remain review-gated.

The app dashboard is the entry surface for this structure. It shows the active case, workbench links, graph orbit, and case-readiness signals for map posture, timeline posture, stakeholders, and marketplace context before the user moves into the workbench.

## How Context Works

PRAXIS context has two main meanings:

1. **User context**: who the user is, their role, preferences, workspace posture, communication style, model/cost preferences, and saved defaults. This guides tone, depth, tool suggestions, and how output is presented.
2. **Situation context**: what the case is about, why it matters, what would change the assessment, the policy question, source receipts, graph nodes, research threads, memo/draft state, and active chapter focus. This guides retrieval, reasoning, citations, and recommendations.

The current workbench begins situation context in the **Context** tab with a four-field frame:

- What is happening?
- Why does it matter?
- What would change the assessment?
- What is the policy question?

That frame is saved as a first-class situation record, queued for Cognee memory as a `Situation` data point, and used by downstream chapters. Research threads add conversation-level context. Library uploads add source context. Ontology and Graph add structured context. The Graph tab explains the case with map projection, timeline, stakeholder analysis, policy/conflict anatomy, and a Cognee/GraphRAG/marketplace handoff. Memos, Draft, ACH, Tools, and Boardroom consume that context but should not silently rewrite canonical facts.

## From Data to Structured Pieces

Raw data enters through uploaded files, user-supplied URLs, demo/source libraries, research results, saved claims, and tool outputs. PRAXIS turns that material into structured pieces:

- **Source receipts**: the durable record that a document, article, transcript, or other source exists for the case.
- **Chunks and passages**: retrievable source segments used for citation and evidence lookup.
- **ACO candidates**: proposed Actors, Claims, Interests, Constraints, Leverage, Commitments, Events, and Narratives extracted from sources or generated by tools.
- **Graph nodes and edges**: canonical reviewed structure, separated from unreviewed candidates.
- **Research threads**: iterative questions and recall history that improve memory coverage.
- **Memos, drafts, ACH matrices, and tool runs**: work products that use the substrate and keep their provenance attached.

The symbolic firewall posture is intentionally pragmatic: hard invalid writes should be rejected, but low-confidence or incomplete context is usually advisory, not blocking. PRAXIS should let users store text, AI generations, context dumps, and rough source material, while clearly labeling what is raw, synthesized, candidate, reviewed, or canonical.
