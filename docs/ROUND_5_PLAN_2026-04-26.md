## North-Star Reaffirmed

PRAXIS is the **AI-native workspace for policy, diplomacy, and political
analysis**. Every brick below ladders up to one of three user outcomes:

1. The analyst sees what changed and what to do — before they ask.
2. Every figure is sourced and defensible in a UNSC informal.
3. A team of expert AI agents reasons over the same evidence the
   analyst has, with persistent profile and situation memory.

### 47. Brief Builder agent (NEW agentic workflow #3)

- **Persona impact**: diplomat, mediator.
- **What changes**: a new `/api/ai/brief-builder` route runs the
  Synthesis Chair persona (`src/lib/agents/registry.ts`) over the
  active situation's recent tool outputs (last 7 days) + analyst
  notes + corpus, producing a versioned, lock-able UNSC-style brief
  with named decision points and per-section provenance. Calls the
  generalized `runAgent()` from Lane Z.
- **GCP path**: Cloud Run frontend API + Firestore for versioned
  briefs.
- **Files**: `src/app/api/ai/brief-builder/route.ts`,
  `tests/services/brief-builder-schema.test.ts`,
  `src/app/app/brief-builder/page.tsx`.
- **DoD**: 58/4 calibrated routes, Zod schema covers BLUF + sections
  + provenance + lock state, page renders + persists.

### 49. Daily Brief auto-generation 06:00 local — Cloud Scheduler

- **Persona impact**: diplomat, humanitarian lead.
- **What changes**: per-situation cron job writes the Daily Brief

- **Files**: `infrastructure/scheduler/daily-brief-cron.yaml`,

## Google Cloud + Firebase research summary

Round-3 `docs/GCP_EXPANSION_PLAN_2026-04-26.md` already enumerates 12
services. This round adds research on a few more that are immediately
relevant to the analyst-facing experience:

### Already-ranked (from round-3 plan)
- **Document AI** — OCR scanned PDFs (Brick #31).
- **Cloud Translation** — multilingual calibration (Brick #32).
- **Vertex AI Search** — alternate corpus retrieval (Brick #16).
- **Cloud Workflows** — pipeline orchestration (Brick #33).
- **Cloud KMS** — cookie/session secret rotation (Brick #34).
- **Vertex AI Eval** — model regression catch (Brick #35).
- **Cloud Armor** — WAF / rate-limit at edge (Brick #36).
- **Vertex AI Pipelines** — embedding refresh orchestration (Brick #37).
- **IAP** — admin gating (Brick #38).

### NEW additions for round 5

- **Vertex AI Vector Search (was Matching Engine)** — production-
  grade vector index with billions-of-vectors scale. PRAXIS today
  uses Firestore vector indexes (good for documents/chunks); when we
  pass ~1M total chunks across customers, migrate to Vertex Vector
  Search. Track: query latency on the documents layer.
- **BigQuery Vector Search (preview)** — for analytics-side semantic
  search across `tool_runs.outputSummary` + `system_events` and
  cross-customer trend analysis (with PII scrubbed). Pairs with the
  existing `praxis_analytics` dataset.
- **Eventarc Advanced** — event filtering for `graph_updates` /
  `tool_runs` so workers only fire on the relevant subset (Brick #20
  consumers).
- **Cloud Run Jobs** — already noted as the worker-pool fallback;
  also useful for the Daily Brief cron (Brick #49) so we have a
  documented swap path when worker pools change.
- **Firebase Data Connect** — typed SQL-backed contract on top of a
  Cloud SQL Postgres for the parts of PRAXIS that need relational
  guarantees (audit logs, billing reconciliation) where Firestore is
  awkward. Track this as a future option.
- **Firestore Bundles** — pre-package situation snapshots that an
  enterprise customer can take offline / air-gap. Useful for
  customers in classified-adjacent environments.
- **Cloud CDN + Cloud Storage signed URLs** — already used for
  uploads; add CDN in front so document downloads from large customers
  don't hammer Cloud Run egress.
- **Firebase App Check** — bot mitigation on the public landing
  pages and `/api/*` (already partially provisioned per `audit:gcp`;
  enforce mode flip is the brick).
- **Vertex AI Generative AI Studio prompts management** — central
  registry for tool prompts (today they live in route files); allows
  non-engineer copy edits without redeploys. Track as a future
  option.

### Firebase services we're underusing

- **Firebase Extensions** — `firestore-bigquery-export` would stream
  `tool_runs` + `system_events` to BigQuery automatically (BIG #26).
  Saves writing the streaming function.
- **Remote Config** — for feature-flagging the new agent lanes
  (Source Scout, Red-Team, Brief Builder) so we can enable them per-
  customer in production without redeploys.
- **Firebase ML / Genkit** — backend already uses Genkit; expand
  client-side ML predictions for low-latency reranking of corpus
  results.
- **Firebase Cloud Messaging (FCM)** — push notifications for the
  notification bell (Brick #52) when the analyst is offline.

## Operating principles (carrying over)

1. Every AI route uses `withCalibration` with the right toolId + credit
   op. Audit gate enforces this.
2. Every persona used in an agentic workflow is registered in
   `src/lib/agents/registry.ts`.
3. Every long-running deliberation writes to `tool_runs`,
   `background_jobs`, `system_events`, `dev_backlog`.
4. Every commit lands as `giuliocatanzariti@gmail.com`, no
   Co-Authored-By trailer, push to `main`, deploy via Cloud Build.
5. Every doc change updates: CHANGELOG, CONTINUATION, the relevant
   tool/spec doc, and the TODO board row.
6. Light-mode tokens only on app surfaces (`navy-` + `slate-` scale).
7. Auto-publish to `dev_backlog` on every 4xx/5xx so the next agent
   sees the friction.
